# Neobitcoin paper bot: disaster recovery

This runbook restores honest paper state. It never restores by inventing market
events, exits, fills, or delivery acknowledgements. The existing research
collector is outside this recovery domain and must remain independently active.

## Invariants to preserve

During every incident:

- `PAPER_ONLY=true`; no live-execution code or broker order capability is added;
- exact instrument UID/name/ticker/class must match before strategies run;
- live trading status and data-quality gates remain fail-closed;
- each immutable strategy version keeps its own account and state;
- stable IDs/idempotency prevent duplicate orders, fills, positions, archives,
  or same-task deliveries;
- undelivered archives and current SQLite state are never retention-deleted;
- active `.inprogress` files are recovered/materialized, never bundled directly;
- the collector's services, code, config, credentials, and data are not touched.

## First response

1. Record UTC/MSK time, symptom, last known good event/archive/delivery, disk
   state, unit PID/restart count, and incident correlation IDs.
2. Check `neobitcoin-paper.service`, archive/delivery timers and one-shot units,
   loopback health/readiness, and structured journal.
3. Verify `neobitcoin-research.service` independently and capture its PID/
   restart count. Do not restart it as part of paper recovery.
4. If integrity is uncertain, stop new paper entries by stopping or pausing only
   the paper service. Preserve state and evidence before any repair.
5. Do not display credential files, full environment, full task ID, or sensitive
   journal fields.

## Process crash or kill -9

Expected automatic path:

1. systemd detects the exit and restarts `neobitcoin-paper.service` after its
   bounded restart delay;
2. SQLite opens with foreign keys, WAL, `synchronous=FULL`, busy timeout, and a
   new restart generation;
3. one transaction recovers active session, immutable strategies, accounts,
   checkpoints, open virtual orders/positions, pending archives, and outbox;
4. interrupted delivery claims return to retryable state;
5. stream subscriptions are rebuilt and acknowledged;
6. entries remain blocked during reconnect warmup;
7. deterministic IDs and idempotency keys reject replay duplicates.

Operator verification:

```bash
sudo systemctl show neobitcoin-paper.service \
  -p ActiveState -p SubState -p MainPID -p NRestarts -p ExecMainStatus
curl --fail --silent http://127.0.0.1:8787/healthz
curl --fail --silent http://127.0.0.1:8787/readyz
sudo journalctl -u neobitcoin-paper.service --since '-10 min' --no-pager -o cat
```

Compare recovered open-order/position IDs and account equity with the pre-fault
snapshot. Confirm no repeated fill/trade IDs and no second outbox key. A restart
that loses an open position or manufactures a closing price is a failed recovery.

## VPS reboot or host outage

The main service and archive/delivery timers are boot-enabled and depend on
`network-online.target` where network is needed. Timers are persistent.

After the host returns:

1. verify all three runtime units are enabled and active;
2. perform the process-crash verification;
3. confirm the application uses `Europe/Moscow`, not host local time;
4. discover any unfinished prior Moscow session before starting a new one;
5. allow the persistent archive timer to finalize an eligible prior session;
6. allow the delivery timer to retry queued archives;
7. verify exact instrument snapshot and live status subscription;
8. verify the collector independently and compare its state with the pre-outage
   capture.

Host reboot testing must be coordinated because it necessarily interrupts the
collector. If the mandate is that the collector not be stopped, validate boot
enablement and use an isolated restart/fault simulation instead; record that an
actual host reboot was not performed rather than claiming otherwise.

## T-Invest stream, DNS, or API outage

The safe state is connected=false and entry gate closed. The runtime records the
disconnect, gap, generation, and last event. Reconnect uses exponential backoff
with jitter, recreates every subscription, checks acknowledgements, and backfills
only data the official API can honestly provide (for example candles and latest
observations). It never synthesizes the missing book.

Open paper positions remain in SQLite with a quality marker. If no valid causal
book is available, an exit is not fabricated. Once status, acknowledgements, and
valid events return, complete warmup before new entries and apply the version's
conservative frozen recovery/exit policy.

Verify reconnect generation increment, restored subscriptions, acknowledged
depth/candle/status requests, gap markers in the archive, and no duplicate event
or order generated by replay.

## Malformed event or strategy failure

A malformed event is quarantined/rejected at normalization, increments the
quality/error record, and cannot reach execution. A strategy exception or timeout
is scoped to that version; its error is stored, its failure counter advances, and
its circuit may open. Other versions and ingest continue.

Do not disable validation or widen exception catches to force readiness. Repair
the parser/plugin, add a regression test, release a new strategy version if logic
changes, then replay only causal source evidence.

## SQLite busy, failed quick check, or suspected corruption

For a transient busy condition, let the configured busy timeout and transaction
retry policy act. Never copy only the SQLite main file while WAL writes are
active.

If `quick_check` fails:

1. stop only `neobitcoin-paper.service` and the two paper timers;
2. preserve the database, `-wal`, `-shm`, active writers, journal, release SHA,
   and filesystem metadata as restricted incident evidence;
3. locate the latest verified online SQLite backup;
4. validate the backup read-only with `quick_check` before use;
5. move the corrupt set to a restricted quarantine path without deleting it;
6. restore the complete verified backup atomically with correct ownership/mode;
7. start the paper service and reconcile recovery snapshot against Parquet,
   deterministic IDs, and the last checkpoint;
8. keep entries closed until no duplicate/lost open state remains.

If no verified backup exists, reconstruct only from independently validated
checkpoints/events and record uncertainty. Never infer an unobserved fill or
delivery acknowledgement.

## Writer exception or unfinished Parquet

Active append files are JSONL ending in `.inprogress`; finalized daily files are
one typed ZSTD Parquet per dataset. On recovery:

1. stop ownership of the affected session writer;
2. parse complete JSONL records and isolate a truncated tail as evidence;
3. materialize into a temporary output using the fixed Arrow schema;
4. validate primary keys and full dataset contract;
5. atomically publish only after success;
6. retain/quarantine the failing source and report if materialization fails.

Never rename an incomplete output to `.parquet`, and never include `.inprogress`
in a daily archive.

## Archive build or validation failure

The artifact is not deliverable. Keep or move the failed output to
`quarantine/`, write an archive failure report, retain the session inputs, and
retry materialization from closed writers. The validator must independently pass
PyArrow, DuckDB, exact schemas, IDs/foreign keys, duplicates/timestamps, exit
ordering, PnL/position/equity, lineage/event-window coverage, secret scan,
`SHA256SUMS`, archive SHA, and zstd/tar.

Do not edit `MANIFEST.json`, `VALIDATION_REPORT.md`, or a sidecar to turn FAIL
into PASS. A rebuilt byte sequence gets its own SHA and idempotent archive record.
If delivery works, send an error notification rather than the bad archive.

## Delivery outage or duplicate attempt

Delivery failure never blocks ingest or archive retention. Verify the artifact
again, then inspect outbox state:

- `FAILED_RETRYABLE`: leave durable; timer retries with backoff/jitter;
- interrupted `DELIVERING`: recovery resets/reclaims it;
- `DELIVERED` without completion acknowledgement: verify the exact turn before
  moving to `ACKNOWLEDGED`;
- `QUARANTINED`: repair the artifact/transport; do not force a transition;
- duplicate key: reuse the existing record and never announce as new.

Repair official App Server authentication/task access or the allow-listed
read-only artifact transport. Resume the stored existing task, verify the same
task ID and completed turn/run ID, and prove Codex can open/hash the artifact.
Never create a new task, automate a browser, or expose a public directory.

## Low disk

Default free-space thresholds are warning 5 GiB, critical 2 GiB, emergency
1 GiB. At critical/emergency:

1. disable new entries;
2. checkpoint SQLite and close writers safely;
3. preserve runtime state and every undelivered archive;
4. suppress optional extended telemetry if configured;
5. identify growth using `df`/`du` without following untrusted links;
6. remove only allow-listed temporary data or acknowledged archives beyond
   retention;
7. restore free space, validate state/writers, and warm up before entries.

Never recursively delete a computed/wildcard path. Undelivered artifacts and
their manifests/hashes are not emergency cleanup candidates.

## Credential exposure or identity mismatch

If a credential may have leaked:

1. stop only the component that consumes it;
2. restrict evidence; do not repeat the value in logs/chat/report;
3. revoke/rotate through the provider's supported mechanism;
4. install replacement through stdin as root, owner `root:root`, mode `0600`;
5. verify absence from Git, environment example, arguments, `/proc` cmdline,
   journal, snapshots, reports, manifests, and archives;
6. restart the minimum unit and revalidate.

Do not test token scope by placing an order. The local paper-only boundary must
block live execution before any network call.

An instrument UID/name/ticker/class mismatch immediately pauses strategies.
Preserve the old snapshot, rediscover exact metadata through read-only instrument
methods, and perform a reviewed migration. Never fall back to a partial name.

## Bad release and rollback

The installer stages immutable releases under
`/opt/neobitcoin-paper-releases`, atomically switches the
`/opt/neobitcoin-paper` symlink, and records prior unit states. On failed tests,
migration, unit activation, or health, it restores the previous symlink/units and
their enabled/active state.

For a post-deploy regression, capture evidence, stop new entries, switch only to
a previously validated paper release using the same atomic installer/rollback
mechanism, run migrations only when backward-safe, then execute the full recovery
and exact-instrument checks. Do not use the collector checkout or release as a
paper rollback target.

## Fault-injection acceptance matrix

| Fault | PASS evidence |
|---|---|
| kill -9 | new PID/generation, state restored, no duplicate IDs |
| stream disconnect | gap recorded, all subscriptions re-acknowledged, warmup enforced |
| DNS/API unavailable | backoff/jitter, entries closed, service survives/recovers |
| malformed event | rejected/error recorded; no execution effect |
| SQLite busy | bounded retry/recovery; transaction/state intact |
| writer exception | active data recoverable; no false finalized Parquet |
| disk warning/critical | metrics/event, new entries closed at policy threshold |
| archive failure | quarantine/report/rebuild; invalid artifact not delivered |
| Codex failure | durable retry; trading unaffected; same-task acknowledgement later |
| restart with open position/order | exact IDs/trailing/account restored |
| duplicate replay/delivery | idempotent existing result, no new trade/turn announcement |
| reboot simulation | enabled units/persistent timers/recovery proven; actual reboot truthfully recorded |

Record exact commands, timestamps, before/after PIDs, restart generations, hashes,
and assertions in the timestamped final report. A test that was not executed is
`PENDING` or `FAIL`, never assumed PASS.

## Return-to-service gate

Resume new paper entries only when:

- safety/source scans and the live-order-block test pass;
- exact instrument identity and current status subscription pass;
- SQLite and recovered account/order/position state reconcile;
- required subscriptions are acknowledged and warmup is complete;
- health and readiness are green, queues bounded, disk above warning threshold;
- no unexplained duplicate or unobserved fill/exit exists;
- previous completed session archive/delivery state is consistent;
- collector remains independently active and unchanged.
